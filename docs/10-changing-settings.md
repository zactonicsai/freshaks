# 10 · Changing settings (sed, set-config.sh, Helm values, realm re-import)

## The one rule

**Settings live in `scripts/00-config.sh`.** Every script sources it. Values discovered while running (registry name,
ingress IP, base domain) are appended to `scripts/.generated.env`, which is also sourced. Never edit rendered files.

## sed in 60 seconds

`sed` = *stream editor*. The command everyone uses is **substitute**:

```
sed 's|OLD|NEW|' file          # replace the first OLD on each line — prints to screen
sed -i 's|OLD|NEW|' file       # -i = edit the file in place (macOS: sed -i '' ...)
```

`|` is the separator; you may use `/`, but URLs contain `/`, so `|` is less annoying. `^` means *start of line*,
`.*` means *anything*. So

```bash
sed -i 's|^export LOCATION=.*|export LOCATION="westeurope"|' scripts/00-config.sh
```

means: on the line that *starts with* `export LOCATION=`, replace the whole line. That is exactly what
`tools/set-config.sh` does (plus: append the line if it does not exist, and macOS/Linux sed differences):

```bash
tools/set-config.sh LOCATION westeurope
tools/set-config.sh APPS_NODE_COUNT 3
tools/set-config.sh ENABLE_TLS true
tools/set-config.sh LETSENCRYPT_EMAIL me@example.com
```

## Which script to re-run after a change

| You changed | Re-run |
|-------------|--------|
| region, VM sizes, node counts | `01`, `02` (node pools can't change size in place — `99-destroy.sh --keep-cluster` then `02`, or add a new pool) |
| `ENABLE_TLS` / `LETSENCRYPT_EMAIL` | `02` (cert-manager), `05` (Keycloak hostname → https), `08` (ingresses), then `tools/reimport-realm.sh` (redirect URIs) |
| Keycloak admin password | `05` only applies on first start — change it in the admin console, then update the config |
| `DEMO_USER_PASSWORD`, client secrets | `tools/reimport-realm.sh` **and** `08` (the apps get the secret from a Secret) |
| anything in `helm/keycloak/values.yaml` | `05` (it runs `helm upgrade`) |
| `IMAGE_TAG` after code changes | `07`, then `08` |
| the realm JSON | `tools/reimport-realm.sh` |

## Helm values: three ways

```bash
# 1. edit values.yaml with sed (top-level keys)
tools/set-config.sh --yaml helm/keycloak/values.yaml logLevel debug

# 2. --set for nested keys, one-off
helm upgrade --install keycloak helm/keycloak -n identity -f helm/keycloak/values.yaml \
  -f helm/keycloak/values-generated.yaml --set resources.requests.memory=1536Mi

# 3. a new values file layered on top (values on the right win)
helm upgrade --install keycloak helm/keycloak -n identity -f helm/keycloak/values.yaml \
  -f helm/keycloak/values-generated.yaml -f my-overrides.yaml
```

`values-generated.yaml` is regenerated by script 05 only when missing (or `REGENERATE_VALUES=true scripts/05-install-keycloak.sh`).
Because the deployment carries a `checksum/secret` and `checksum/realms` annotation, changing a password or the realm
file automatically restarts the pod on `helm upgrade`.

## Realm changes

* Edit `helm/keycloak/realms/grocery-realm.json` (add a user, a role, a client) → `tools/reimport-realm.sh`.
* Or click in the admin console — then export: `tools/kcadm.sh get realms/grocery` (settings) and
  `tools/kcadm.sh get clients -r grocery`, and paste what you need into the JSON so it is not lost.
* Roles: `tools/add-role.sh <name>` does both (live + file).

## Secrets: what is where

| Secret | Namespace | Keys | Consumer |
|--------|-----------|------|----------|
| `postgres-secret` | data | admin/keycloak/app passwords | Postgres init |
| `openldap-secret` | identity | admin password | OpenLDAP |
| `keycloak-secret` (Helm) | identity | bootstrap admin, DB user/password | Keycloak |
| `app-db-secret` | apps | DB_URL, DATABASE_URL, user, password | both apps |
| `oidc-secrets` | apps | JAVA/PYTHON_CLIENT_SECRET, FLASK_SECRET_KEY | both apps |
| `test-config` | testing | URLs + demo password | the inspectors |

For real deployments move these to Azure Key Vault (the *Secrets Store CSI driver* mounts them as files) — the
scripts already keep secrets out of the repo, which is step one.
